# EXAONE 도구 바인딩 시 답변 품질 이슈

엑사원을 `bind_tools`로 감싼 상태에서, 모델이 질문에 **직접 답하지 않고** 도구 설명·제안 위주로 응답하는 현상 정리.

## 현재 구조

- **래퍼**: `ExaoneLangChainWrapper` (`app/domain/models/bases/exaone_model.py`).
- **도구 바인딩**: `bind_tools`로 `analyze_with_exaone`, `search_documents` 등 연결.
- **시스템 프롬프트**: 기존 시스템 메시지 뒤에 `TOOL_CALLING_SYSTEM_PROMPT` + 도구 목록을 항상 붙임. 형태: `[역량 전문가 프롬프트]\n\n[TOOL_CALLING_SYSTEM_PROMPT + 도구 목록]`.

## 문제 원인

1. **토큰 비중**: 도구 프롬프트(도구 설명, JSON 규칙)가 길어 시스템 프롬프트에서 비중이 커짐.
2. **역할 우선순위 모호**: "역량 전문가로 답변하라" vs "도구 호출 시 JSON으로만 응답하라"가 동시에 있어, 모델이 도구 제안 쪽으로 치우침.
3. **도구 편향**: "사용 가능한 도구" 목록이 항상 노출되어, 도구를 언급·제안하는 응답이 늘어남. "도구 불필요 시 일반 텍스트로 응답" 문장이 상대적으로 약함.
4. **지시 충돌**: 역량 전문가(직접 답변) vs 도구 프롬프트(JSON·호출 규칙)가 섞여 "직접 답변 대신 도구 설명" 같은 중간 응답이 나옴.

## 개선 후보

- **프롬프트 순서·비중**: 역량 프롬프트 유지, 도구 섹션은 짧게. "직접 답변 우선, 필요할 때만 도구 사용" 명시.
- **조건부 도구 프롬프트**: 질문 유형·메타데이터에 따라 도구 프롬프트 생략/축소.
- **도구 프롬프트 내용**: 상단에 "질문에 먼저 직접 답하고, 필요한 경우에만 도구 호출" 두고 JSON 규칙은 최소화.
- **분리된 래퍼**: 도구 필수/선택 경로를 나누고, RAG 답변 경로에서는 도구 프롬프트를 넣지 않거나 최소화.
