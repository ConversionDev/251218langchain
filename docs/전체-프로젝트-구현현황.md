| 항목 | 내용 |
|------|------|
| **명칭** | RAG (역량·공시·LLM 기반 인사·성과 플랫폼) |
| **비전** | 역량·공시 데이터와 LLM을 결합해 **인사·성과·공시까지 이어지는 AI 플랫폼** 구축 |
| **핵심 도메인** | 역량(Success DNA)·공시(disclosures)·LLM(ExaOne)·플랫폼(채팅, 이력서 분석, 성과 대시보드, 직원/신입 관리, 메일·스팸 등) |

### Success DNA (5대 역량)

| 역량 | 설명 |
|------|------|
| 리더십 | 팀·과제 리드, 의사결정·책임 |
| 기술력 | 직무 관련 기술·도구 숙련도 |

| 협업 | 소통·협력·조직 기여 |
| 적응력 | 변화 대응, 학습·유연성 |

- **산출**: 이력서 원문을 LLM으로 분석해 각 역량 0–100 점수. **활용**: Core 직원 등록·신입 관리·성과 대시보드·방사형 차트·직무 전환 분석.

## 3. 시스템 아키텍처

### 3.1 흐름

- **클라이언트** → FastAPI(CORS) → `/api/*`(REST), `/internal/*`(LLM 프록시), `/mcp`(MCP)
- **도메인**: domain.hub.orchestrators(chat, spam, graph, disclosure), domain.hub.repositories, domain.hub.llm
- **데이터**: PostgreSQL + pgvector, Alembic 마이그레이션

### 3.2 스타 토폴로지 (Hub-Spoke)

중앙 **Hub**가 요청을 받아 **Chat MCP / Spam MCP**로만 위임. Hub는 ExaOne·LLaMA를 직접 로드하지 않고, 각 MCP가 Spoke URL로 `call_tool`하며 Spoke가 필요 시 Hub 내부 API를 호출.

```
                        [ 클라이언트 ]
                              │
                              ▼
                   [ FastAPI 게이트웨이 ]
                     /api/*  /mcp  /internal/*
                              │
                              ▼
              ┌────────────────────────────────┐
              │     Hub (Central Control)       │
              │   /mcp  FastMCP · call_tool     │
              └────────────────────────────────┘
                        │              │
              ┌─────────┘              └─────────┐
              ▼                                   ▼
     ┌─────────────────┐                 ┌─────────────────┐
     │   Chat MCP      │                 │   Spam MCP      │
     │ /internal/mcp/  │                 │ 이메일·스팸 분류 │
     │ chat, chat-spoke│                 └────────┬────────┘
     └────────┬────────┘                         │
              │                                   ▼
              ▼                          ┌─────────────────┐
     ┌─────────────────┐                 │  Spam Spoke     │
     │  Chat Spoke     │                 │ LLaMA 스팸 분류 │
     │ ExaOne 채팅 등  │                 └────────┬────────┘
     └────────┬────────┘                         │
              └──────────────┬────────────────────┘
                             ▼
                   [ Hub 내부 API ]
                   /internal/llama, /internal/exaone
                             │
                             ▼
                   [ PostgreSQL · pgvector ]
```

| 구성요소 | 역할 |
|----------|------|
| **Hub** | `/mcp` 마운트. Chat MCP / Spam MCP로만 라우팅. |
| **Chat MCP / Spoke** | 동일 프로세스. 채팅·RAG ExaOne. Spoke가 Hub ExaOne API 호출. |
| **Spam MCP / Spoke** | 이메일·스팸 분류. Spoke가 Hub LLaMA API 호출. |

## 7. 실행·배포 (runbook)

### 7.1 프론트엔드

- **실행**: `cd frontend` → `pnpm install` → `pnpm dev` → http://localhost:3000
- **환경**: `.env.local`에 `NEXT_PUBLIC_API_URL=http://localhost:8000`
- **빌드**: `pnpm build` / `pnpm start`

### 7.2 백엔드

- **실행**: `cd app` → `uvicorn fastapi_server:app --host 0.0.0.0 --port 8000` (또는 main.py)
- **DB**: `DATABASE_URL` 또는 `POSTGRES_CONNECTION_STRING`, `AUTO_MIGRATE=true` 시 기동 시 `alembic upgrade head`
- **스타트업**: DB만 확인. ExaOne·Embedding·FAISS·스팸 LLaMA는 **첫 요청 시 lazy 로드**. RAG는 pgvector만 사용(FAISS 미로드).

### 7.3 배포

- **프론트**: `NEXT_PUBLIC_API_URL` 설정 후 빌드.
- **백엔드**: `CORS_ORIGINS`(쉼표 구분). DB 연결·lazy 로드로 t3.small 등 소형 인스턴스 가능.

## 8. 성능·비용·UX (구현된 개선 사항)

| 구분 | 구현 내용 |
|------|-----------|
| **시간 감소** | 임베딩 배치 처리(32·512). 채팅 스트리밍(SSE). 이력서 분석 세션 캐시(동일 파일 즉시 반환). |
| **인프라 비용** | Lazy 로딩(스타트업 시 DB만, ExaOne·Embedding·LLaMA 첫 요청 시 로드). FAISS 미로드·pgvector만 사용. |
| **리소스** | 임베딩 모델 싱글톤·캐시. ExaOne/LLM 추론 후 `torch.cuda.empty_cache()`. 스팸 분류 배치(batch_size=32). |
| **로딩·UX** | 채팅 스트리밍으로 첫 토큰 대기 단축. 이력서 캐시로 재선택 시 즉시 반영. 직원·신입 목록 페이지네이션(20건). 로딩 UI(버튼 disabled·로딩 문구). |
