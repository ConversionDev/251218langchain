# 배터리만 깔끔하게 정리하는 전략 (env_mapping 전체 참고)

**기준**: `app/data/env_mapping/환경 데이터 매핑 테이블.xlsx` 의 **형식(열 구조·행 규칙)** 을 그대로 따른다.  
**목표**: env_mapping 폴더에 흩어진 배터리 관련 데이터를 이 형식 하나로 통합해, “배터리 전용” 시트 한 덩어리로 정리한다.

---

## 1. 기준 형식 (환경 데이터 매핑 테이블.xlsx)

- **열**: 내부 표기명, 표준그룹, CAS 번호, EC 번호, 영문명, MSDS 기준명, 관련 ESG 지표, 산업 분류, 필수/선택, 표준 단위, 비고  
  (필요 시 GESTIS 검증·PubChem 검증·NCIS 참조 등 부가 열 추가 가능하되, **기본 11개 열은 원본과 동일** 유지.)
- **행 규칙**: **1행 = 1별칭(내부 표기명)**. 동일 물질이라도 표기명/동의어가 다르면 별도 행. 완전 동의어만 행 추가.
- **정렬/중복**: CAS 기준으로 묶어서 관리하고, (CAS, 내부 표기명) 조합은 중복 제거.

이 구조를 “배터리만 정리”할 때도 그대로 따른다.

---

## 2. env_mapping에서 참고할 데이터

| 자료 | 역할 |
|------|------|
| **환경 데이터 매핑 테이블.xlsx** | **형식의 기준**. 열 이름·행 규칙·단위 등은 여기 맞춤. |
| **battery_substances.csv** | 배터리 “물질 목록” 마스터. CAS, name_en, name_ko, battery_related=1 인 것만 배터리로 취급. |
| **배터리 산업 공급망 리스트 보강.xlsx** | 배터리 도메인에서 이미 정리된 **CAS·EC 매핑**. EC 1차 출처로 사용. |
| **환경데이터_매핑_보강.xlsx** | 전 물질 보강본. 배터리만 필터할 때 “원본 형식 + 보강된 EC·명칭” 참고용. |
| **zvg-cas-list-d.xlsx (GESTIS)** | CAS·EC·ZVG 테이블. EC 2차 출처·검증용. |
| **mapping_*.xlsx** | 다국어 매핑. 배터리만 정리 시에는 필요 시 CAS 기준으로 물질명·동의어 참고. |
| 전력수요·전력배출계수 등 | 배터리 “물질” 매핑과는 별도. 같은 폴더에 있지만 배터리 정리 전략에서는 제외. |

정리하면: **형식은 환경 데이터 매핑 테이블.xlsx**, **물질 범위는 battery_substances + 공급망 리스트**, **EC·검증은 공급망 → GESTIS → PubChem 순**으로 채운다.

---

## 3. 배터리만 정리하는 작업 흐름

1. **물질 범위 확정**  
   - `battery_substances.csv` 에서 `battery_related=1` 인 CAS를 기준 목록으로 사용.  
   - `배터리 산업 공급망 리스트 보강.xlsx` 에만 있고 CSV에는 없는 CAS가 있으면, “배터리”로 쓸지 결정 후 필요 시 CSV에 반영해 목록 통일.

2. **형식 맞추기**  
   - 출력 시트는 **환경 데이터 매핑 테이블.xlsx 와 동일한 11개 열**을 기본으로 한다.  
   - 각 행: 내부 표기명, 표준그룹(BAT), CAS 번호, EC 번호, 영문명, MSDS 기준명, 관련 ESG 지표(예: 배터리 원자재), 산업 분류(예: 배터리 제조), 필수/선택, 표준 단위, 비고.  
   - 1행 = 1별칭이므로, 같은 CAS라도 영문명 1행·국문명 1행(다를 때)·동의어(완전 동의어만) 별도 행으로 둘 수 있음.

3. **EC 번호 채우기**  
   - **1차**: 배터리 산업 공급망 리스트 보강.xlsx 에서 CAS로 EC 조회.  
   - **2차**: GESTIS(zvg-cas-list-d.xlsx)에서 CAS로 EC 조회.  
   - **3차**: PubChem API 등으로 EC 조회.  
   - 이미 구현된 `export_battery_only` + `supply_chain_ec_lookup` + `gestis_lookup` + PubChem 순서가 이 전략을 그대로 반영한 것.

4. **검증·부가 열(선택)**  
   - GESTIS 검증, PubChem 검증(CID 등), NCIS 참조 등은 “같은 형식 안에서 부가 열”로 두고, 4출처를 남기고 싶을 때만 추가. 기본 11개 열만 써도 “환경 데이터 매핑 테이블 형식”에는 맞음.

5. **산출물**  
   - **배터리 전용 Excel 1개**:  
     - 시트 구조 = 환경 데이터 매핑 테이블.xlsx 와 동일(열·행 규칙).  
     - 포함 행 = 배터리 물질만(CAS 기준 목록 + 위 EC 채우기 규칙).  
   - 파일명 예: `환경데이터_매핑_보강_배터리.xlsx` 또는 `배터리_환경데이터_매핑.xlsx` (팀 규칙에 맞게).

---

## 4. 유지보수·역할 나누기

- **battery_substances.csv**: 배터리 “어떤 물질을 넣을지”의 **마스터 목록**. 신규 배터리 물질 추가·제거는 여기서.
- **배터리 산업 공급망 리스트 보강.xlsx**: 배터리 공급망에서 **검증된 CAS·EC·분류** 참고용. EC 1차 출처이자 검증용.
- **환경 데이터 매핑 테이블.xlsx**: 전체 환경 데이터의 **형식 표준**. 배터리 전용 시트도 이 형식을 따르기만 하면 됨.
- **환경데이터_매핑_보강.xlsx**: 전 물질 보강본. 배터리만 쓰고 싶을 때는 “배터리만 필터한 버전”을 따로 두고, 그 버전의 형식은 위 기준 테이블과 동일하게 유지.

---

## 5. 요약

- **형식**: 환경 데이터 매핑 테이블.xlsx 의 **11개 열 + 1행=1별칭** 규칙을 그대로 따른다.  
- **범위**: battery_substances(battery_related=1) + 필요 시 공급망 리스트 보강의 CAS로 “배터리만” 한정.  
- **EC**: 공급망 리스트(1차) → GESTIS(2차) → PubChem(3차) 순으로 채우면, env_mapping 전체 데이터를 참고해 깔끔하게 배터리만 정리할 수 있다.

이렇게 하면 **기준 구조는 원본 한 곳(환경 데이터 매핑 테이블.xlsx)** 에만 두고, **배터리는 그 구조에 맞춘 “필터 + EC 보강” 결과**로만 정리할 수 있다.
